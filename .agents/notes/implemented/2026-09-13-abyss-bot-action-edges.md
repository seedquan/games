# 游玩机器人保留输入边沿

Status: implemented

## Context

0.18.0 长枪机器人多次在第二舱阵亡，不能据此直接降低敌人或提高武器数值。新增只读受击诊断观察既有玩家受击特效及同步脚本调用栈；一个失败样本的九次受击全部来自弹丸，冲刺和弹反冷却均为零。原策略仅对近身前摇和区域危险做防御，新增弹道策略的首次对照又没有实际返弹。

最小场景确认：在 `physics_frame` 协程中每步释放再按下技能，会在角色处理前不断刷新输入边沿；按住攻击能生效，不等于依赖 `is_action_just_pressed` 的冲刺、冰冻、弹反得到执行。因此旧驱动的数值与生存样本不能当作使用了完整防御技能的证据。

## Decision

新增测试专用 `tests/bot_input.gd`，仅在意图改变时调用 Input 的按下/释放接口。菜单、终止和清理仍显式释放机器人持有的操作。保留每个物理步采样，适配双人前缀；不直接调用角色技能，不改冷却、耐久、敌人或掉落。

`tests/input_clock.gd` 在正常角色物理处理中验证一次和连续请求、冲刺/冰冻/弹反、实际蓄力与松开发射、第二席隔离，覆盖 1/4/12/16 倍模拟。修正后无界面和 Mac 原生各 57 项通过。早期轨道炮测试误把满蓄力门槛写为 0.9 秒，现读取武器定义中的 0.8 秒；那四项错误属于夹具，不是游戏缺陷。

游玩脚本默认保留原近身/区域危险策略，`--projectile-defense` 独立启用根据弹体相对速度预测碰撞、在原弹反窗口内请求防御的策略。`--trace-damage` 可保存受击调用栈和附近弹体，限定最多 512 条。报告分开记录输入适配器、策略、技能冷却上升次数和已退出场景的返弹数，避免把请求过技能误写为成功执行。这个机器人仍具有精确读取战斗状态的能力，不是人类易用性或实体手柄验收。

## Verification and consequences

只修正输入、保留原策略的长枪样本仍在第二舱阵亡，观察到一次冲刺、四次冰冻、一次弹反动作，未返弹。再启用弹道防御后，正常数值长枪完成首六舱和首位守卫，四个战斗舱约 87.9 / 127.4 / 151.2 / 140.0 秒，剩余 71 耐久，记录到 9 次返弹。游戏与物理时钟差约 0.030 秒。样本只能说明现有防御机制可用于推进；没有由这些少量样本推断所有武器或真人难度。

完整验证 27 套 / 27,086 项通过。随后正常数值单人长枪、双人火焰法杖都以修正输入和弹道防御策略通过三十舱，含最终守卫的二十个战斗舱中位数为 134.4 / 121.15 秒，记录到 85 / 93 次返弹及各 10 次热冲击。游戏/物理时钟相差 0.031% / 0.030%；具体报告和限制见 `abyss-protocol-godot/docs/balance.md`。

227 个运行文件哈希与 0.18.0 发行记录一致，无需为测试专用改动重复打包。历史失败报告保留，不用修正后的驱动结果覆盖或直接比较旧驱动的速度。实体双手柄与真人防御教学仍没有新增验收证据。
