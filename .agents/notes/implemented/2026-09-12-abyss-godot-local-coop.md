# 深渊协议：双手柄同屏与宽屏输出

Status: implemented

## Context

用户要求双人手柄同屏共享与 2560×1440 全屏。原先任意编号手柄控制同一个角色，敌人、镜头和安全点只考虑七号。

## Decision

`scripts/local_coop.gd` 管理两席的运行期配对。单人和共享菜单保留通配设备输入，合作战斗使用 `p1_`、`p2_` 的精确设备绑定。两只手柄分别按确认加入，只有已配对且不同的两个设备才能出发。设备编号不写入存档；冷启动和断线后重新认领席位。

一号席与协作机体拥有各自武器、耐久、能量和技能。废料、强化及永久成长共享；一号控制共享菜单，一号倒地时二号接管，两人均可暂停。无友军伤害。倒地后队友可近距离停留修复，清舱自动修复，两人都倒地才结束。敌人选择存活角色，近战/地面危险覆盖所有玩家，遮挡处理考虑两人。

镜头用两人和首领的包围范围确定位置与缩放，向外缩放立即生效。窗口采用 `canvas_items` + `expand`，在 16:9 显示器保留字形比例并扩展视野。全屏使用当前桌面原生输出，macOS 遵循系统刘海安全区，不修改操作系统显示配置。

双人安全点为版本 2，在同一个 profile 事务中增加 `partner` 的完整状态。版本 1 单人安全点继续兼容。校验拒绝缺失/非法的第二角色；两人数据、共享资源、购买记录不能分开提交。

## Alternatives

继续使用通配设备操作两个角色会造成串键；分别保存两个 profile 会让购买/奖励和关卡不同步。固定缩放会让拉开距离的队友离开画面。分屏不符合用户的同屏共享要求。

## Verification

`tests/coop.gd` 使用实际 InputEvent 设备 1/3/7 验证独立输入、非配对设备隔离、独立武器、剧情菜单、倒地修复、真实弹体/地面/近战伤害、断线换编号、双人磁盘续档、整条战役、重开及 QHD 摄像机。原生模式保存 QHD 与系统全屏截图。`scripts/release_check.gd` 同时验证打包程序的双设备输入与单人/双人两个隔离 profile 的跨进程续档。

本机 2560×1440 双人压力测试：900 帧，p50 16.797 ms、p95 21.204 ms、p99 21.9 ms；40 次重开、零孤立节点。普通数值的双人 Input-action bot 已通关十二舱、六段剧情；此证据不代表真人体验或实体手柄验收。目标 Windows 主机仍需实机测试。
