# 深渊协议：Windows 验收结果回传

Status: implemented

## Context

Windows 0.10.1 已交付 `smb://Rog-xx/Games`，但没有 Windows 原生运行结果或实体双手柄验收。共享端会拒绝目录重命名，不能把网络盘上的存档测试失败误判为本地游戏持久化缺陷。

## Decision

将一键验收入口作为版本外层附属文件交付，保留已验证 ZIP 和七个内层游戏文件。入口固定核对本版 EXE/PCK/验证脚本哈希，调用现有 `Verify-Windows.ps1 -Rendered`；验证目录必须在 Windows 本地 TEMP，不能位于 UNC 网络路径。

成功后核对返回报告、原生平台标签、程序哈希与全部阶段结果，仅复制该轮的报告、日志和已知截图。profile/settings 留在本地临时目录。逐文件校验后才写 `handoff.json`，其哈希绑定复制的报告。失败不生成成功凭据，原始日志保留供排查。

结果位于版本外层 `验收记录/<运行编号>/`。读取时先检查成功凭据与报告哈希，再核对是否为当前 EXE/PCK。原生运行报告与实体控制器、显示分辨率及真人操作反馈分开审查，不把自动模拟事件称为实体双手柄验收。

## Verification

源脚本和实际部署的 UTF-8 BOM/CRLF 脚本通过 PowerShell AST 语法检查；Mac 执行在访问游戏或玩家文件前因非 Windows 平台退出。附属文件复制后按字节及 SHA-256 核对。Windows 上的实际执行仍待用户启动。原先的游戏回归没有因本次辅助文件复制而无故重复。

## Revision 2: directory permission failures

用户反馈已打开游戏测试窗口，随后终端报告对 `abyss-windows-…` 的访问被拒绝。尚无完整路径，不能确认 Windows 上具体被拒绝的目录或 ACL。原实现会把成功测试后的报告回传异常直接归为“验收未完成”，且只选 TEMP、不检查其写入与重命名能力。

在独立只读目录复现原代码的两种异常后，增加本地工作区预检和 LocalAppData 备用路径。报告、日志、截图先复制到本地唯一 `diagnostics-*` 目录并校验，然后再回传；共享盘失败保留本地证据，单独显示回传错误与完整目标路径。退出码 0 为测试和回传成功，2 为测试通过但回传失败，1 为测试或本地报告准备失败。原始测试日志保留，不改系统权限，不要求管理员运行。

`tools/test_acceptance_io.py` 在 Mac 使用真实文件系统权限运行 PowerShell，6 项覆盖不可写目录与备用选择、无可用目录诊断、共享盘拒绝、证据缺失、成功校验与存档排除、已有结果保护。失败阶段不产生成功凭据，回传凭据仍最后复制。实际 UTF-8 BOM/CRLF 脚本语法及非 Windows 保护通过。共享盘已更新为修订 2，逐字节回读一致；游戏运行资源 67 项清单及 EXE/PCK/原验证器保持一致。此项不是 Windows 实机修复已验收的声明，需目标机重试回传结果。

## Revision 3: version-bound generation

0.11.0 起使用 `tools/prepare_windows_acceptance.py` 从明确指定的本地构建 JSON 和 ZIP 生成验收入口。生成前核对版本、归档大小与 SHA-256、精确文件集合、包内校验清单及每个文件的实际哈希；再把 EXE、PCK、验证脚本哈希写入模板。未替换的模板不能直接运行，已有交付目录不会被覆盖。输出固定为 Windows PowerShell 兼容的 UTF-8 BOM 与 CRLF，并附验收工具自身清单。生成成功只说明工具与指定发行包绑定，不代表 Windows 已运行。

Windows 导出器的中文源码、说明、日志与报告显式使用 UTF-8，避免 Python 3.11 在 cp1252/cp936 默认代码页下解码失败或生成不能被验收工具读取的报告。PowerShell 执行策略仅通过当前进程参数设置，不修改用户或系统策略。18 项 Python/PowerShell 工具测试通过，覆盖既有权限/回传边界、包篡改、版本错配、关键文件逐项哈希、旧目录保护、中文非 UTF-8 默认环境与完整生成链路。
