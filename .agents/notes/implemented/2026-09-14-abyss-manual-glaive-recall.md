# 回旋刃的主动回收

Status: implemented.

## 原因

0.24.3 的正常输入十八舱观察中，第三守卫有 146 次投掷、144 次去程命中、一次回程命中；145 枚正常收回，没有撞墙或超时。持续绕圈可把固定 0.75 秒后的回程拉偏。0.25.0 的第三守卫仍出现 222.5 秒慢样本。地面回程指引已有，只读提示不能让玩家选择转向时机。

## 行为与取舍

新战役回旋刃保留按住自动往返；出手冷却结束且飞刃仍在去程时，松开并再次按攻击可让同一枚飞刃开始回收。沿用各席实际攻击绑定，不增加按键。短程快返在出手冷却结束前已自动返回，因此仍侧重近距、无需追加输入的快速循环；重返飞刃可以主动牺牲去程距离换取更早的回程。

`player.gd` 将经过防误触门控的按下边沿传给武器；`weapon_controller.gd` 同时核验战役、游戏状态、耐久、出手冷却、弹体归属和去程状态。冷却中的提前按键不排队，按住、键盘重复、菜单恢复的旧按键不触发。回收只调用现有 `begin_return()`，保留命中/掩体判定、伤害、投掷间隔和收回前不能再投；重复按键不会再次乘算伤害。

HUD 复用原主武器位置，可回收时显示原创回程箭头、回收和实际键位；飞行/回收中与倒地仍有独立状态。指南说明时机和走位，构筑说明保留真实数值。没有新增存档字段；旧战役保留自动回程，安全点恢复时没有飞行中的弹体。

## 验证边界

`tests/glaive_recall.gd` 使用真实场景、鼠标点击、重绑键及设备 1/3 肩键，检查按住、早按、暂停恢复、重复回收、真实往返命中、双席归属、重开、旧战役和短程快返。现有接触/回程指引/武器改装与冷续档套件继续覆盖共享路径。

更正后的正常输入对照使用独立 0.25.0 源码副本和当前版本，三条单/双人流程均完成三十舱与六段剧情。攻击决策在出手恢复、飞刃越过目标且距离合适时再次按键，只读位置和冷却，不读命中列表，也不调用回收接口。单人只读伤害分类器另外读取命中列表以区分去回程；双人不套用该分类器。其余走位、防御与正常成长选择不变，前后五守卫的基础攻击一致。这仍是单种子机器人证据，不能替代真人难度或宣称每间舱室稳定两分钟。

最初的观察器先调用父级按住攻击，再同帧松开，制造额外按下边沿；对应节奏结论已撤回。更正驱动在原输入函数内部决定最终攻击状态，每帧只提交一次。旧版/新版单人/新版双人分别记录 989 / 880 / 1335 次请求，全部在冷却结束且越过目标后，最早飞行 0.4167 秒；它们是请求数，不能作为成功回收数。完整更正对照的源码、输入差异和日志哈希记录于 `builds/qa/recall-0260-corrected-comparison.json`，原始失败测量保留于 `recall-0260-input-pulse-original/`。

第三守卫由旧版 222.5 秒变为新版单人 76.7 秒，回程命中由 1/146 次投掷变为 69/71；新版单/双人战斗中位 122.8 / 114.1 秒，但最终守卫 48.6 / 46.5 秒仍偏短。完整回归 37 套 / 29,157 项、原生回收专项 37 项和两平台独立包通过；Windows 实机、实体手柄、共享交付与旧性能未达标项按授权暂跳过。实际交付和测量限制见 `docs/production-readiness.md` 与 `docs/balance.md`。
