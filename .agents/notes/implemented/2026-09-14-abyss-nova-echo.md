# 霜火回响：共享新星的局内祝福

状态：implemented

## 背景与决策

原奖励主要改变武器、元素命中或机体数值，共享新星没有独立成长选择。新增一次性祝福 `nova_echo`：保留新星原来的冻结、60% 基础攻击伤害和十秒冷却；施放后 0.8 秒，在施放位置产生范围 270、45% 基础攻击伤害的火焰回响。它能触发已有热冲击与三层毒素爆燃，为队友电击保留短暂冻结窗口。

回响由 `World/Projectiles` 持有，位置和伤害在施放时固定。倒计时使用物理帧，暂停冻结；换房/重开随世界清理。已施放的回响不跟随角色，也不借用武器命中函数，因此不会附加武器自带元素、符文、终结或汲取。火焰及其非递归二次反应继续使用既有敌人规则，实体掩体阻挡回响与二次爆发。初次新星仍按原范围规则处理。

预备阶段显示按掩体裁切的固定边界、中心火焰图示和环形倒计时；爆发阶段保留边界并向外绘制短线。低闪光设置保留形状。奖励与构筑页共用原创 SVG 冰霜→火焰图解，HUD 仅将该席的新星短名称改为“霜火”。已拥有的一席只显示已获得，避免双人卡片重复整段说明。

## 成长与存档

`SKILL_BOONS` 与六类武器 `ELEMENTS` 分开。新祝福只进入现代战役的普通奖励池，不改变首舱两项武器改装与常规强化，也不进入元素商店或替换承诺的元素奖励。每席只能获得一次，已有的一席保持原样，另一席仍可通过共享选择获得。

按席位存入现有 `enchantments` 字典，使用显式 ID 和整数等级 1；没有新增松散写盘事务。只有现代 schema 3 接受该枚举，拒绝重复等级、浮点数、布尔值等。旧十二舱不提供或应用该祝福，旧 schema 1/2 仍按原规则恢复。原 0.23.0 校验器接受普通 schema 3，但拒绝已装备或待选择的新 ID；旧版的既有只读保护会保留无法恢复的文件，不应将其重新解释为普通元素。

## 验证与限制

核心失败优先复现：21 项中 6 项失败，再实现后全过；原生 UI 前 90 项中 4 项失败，补齐图解、构筑与按席 HUD 后通过。额外断言先复现双人描述重复，再修正已拥有席位的文案。真实按键/非零手柄输入、暂停、角色移动、掩体、无祝福/旧版边界、部分席位资格、两次隔离冷加载和非法等级均有专门覆盖。

源码自检与发行包自检分别验证实际延迟火焰、原位爆发和热冲击；发行存档夹具单独给第二席装备，第二进程检查恢复。正常规则输入机器人只优先选择实际出现的卡，按实际输入请求新星，没有插入祝福、改属性、清敌或改冷却。报告统计真正进入爆发阶段的回响。

压力夹具的 `--nova-echo` 通过正常新星冷却发起双席施放；冻结会影响敌人活动，该模式只能证明此类特效的密集绘制与回收，不能作为帧率改善对照。最终源/原生/正常流程/发行证据以 `docs/production-readiness.md` 为准；真人与实体硬件验收仍保留原边界。
