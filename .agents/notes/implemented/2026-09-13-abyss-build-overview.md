# 局内构筑与武器收益展示

状态：implemented

## 背景与决定

基础攻击 26 不是十八种武器的每击伤害；原有符文说明描述下一级，不能直接用于查看当前构筑。新增 `build_info.gd` 仅计算展示值，区分单发、散弹、蓄力、连锁和当前符文等级，并按战役版本解释自带元素与符文。

构筑页从战斗、暂停、奖励、路线、商店及维修页进入。战斗入口返回暂停；其他入口记住原菜单与可用按钮索引。查看、切换席位和返回不调用随机生成、奖励、修复、消费或存档方法。该临时菜单不加入存档 schema。重配对返回原查看席位，恢复战斗仍须明确操作。

双人祝福共享，但根据各自武器、属性和剩余等级展示收益。奖励卡只放升级对比，完整效果放在支持手柄滚动的构筑页。复用 Tab 与菜单按钮，不引入占用可重绑按键的新快捷键。

## 取舍与验证

不把理论每秒伤害标成实战输出；不把所有弹丸命中视为保证收益。常态直接伤害与元素、终结、临时增伤分别标注。显示函数保持只读，测试对照真实攻击和敌人状态，避免为了显示数值改变战斗公式。

`tests/build_info.gd` 与 `tests/build_menu.gd` 覆盖十八武器、旧版/新版冰冻、自带元素、菜单只读性、奖励热键隔离、双设备菜单权限/重连、返回焦点和说明边界。集成到 `verify.py`，发行包自检也执行构筑页打开和安全返回。原生截图只查看项目外压缩 JPEG。

用户要求 Mac 开发验证完成后再制作 Windows 版本；开发测试使用 Dummy 音频驱动，不改玩家设置。约两分钟的战斗房节奏是后续独立迭代目标，本次信息展示不宣称已完成难度校准。
