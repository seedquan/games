# 深渊协议 · Godot 重制版

位于 `games/abyss-protocol-godot/` 的独立 **Godot 4 / GDScript / 2D** 项目。
交付目标为 **macOS 与 Windows 10/11 64 位**；两者使用相同游戏内容和存档格式。
以原作的俯视角动作战斗和十八种基础武器为基础，提供全中文界面、五大区域、三十舱室的单人或双人同屏救援流程，以及贯穿开场、调查、五场区域守卫战和结局的剧情。

## 开始游戏

使用 **Godot 4.7 标准版**打开 `project.godot`，按 **F5** 运行。
已在本机 Godot 4.7.2、macOS Apple Silicon 上验证。游戏无需 .NET、Node、插件、账号或网络服务。

默认窗口按 Mac 屏幕缩放比例适配，Retina 屏幕上的窗口与文字保持正常桌面尺寸；窗口会自动缩小到当前屏幕可用范围。

```sh
cd games/abyss-protocol-godot
./godot.sh                 # 打开编辑器
./godot.sh --play          # 直接开始游戏
```

启动脚本自动寻找 `godot` / `godot4` 和本机常见安装路径。其他位置可将 `GODOT_BIN` 设为 Godot 可执行文件的绝对路径。Windows 可从 Godot 项目管理器导入。

## 故事

穹灯空间站失联七天，三百一十二名乘客被困在休眠舱。你是维修机器人“七号”，循着首席工程师林澈留下的应急留言，重新进入被自动防御系统封锁的空间站。

沿途的记录逐渐揭示：损坏的温控传感器触发了深渊协议，错误的封锁又开始造成真正的散热危机。你必须恢复供电、夺回维修授权、找回校准数据，最终压制核心的防御系统，让主控重新执行救援。

六段剧情会在必经的关键节点出现，阅读期间战斗暂停。不同路线不会跳过关键线索；机体失效与救援成功有不同的结果。完整设定见 [剧情设定](docs/剧情设定.md)。

**0.16.0：实时剧情过场。** 抵达穹灯、恢复泵组、乘客归航三个节点提供八秒的原创 SVG 分层动画，由 Godot 实时绘制。可随时继续、暂停或重播；画面与舒适度设置可关闭剧情动画，改用静态插画。完整日志和剧情顺序保留，动画不推进战斗或消耗资源。

**0.17.0：近战动作与出手反馈。** 长枪直刺、重锤砸击、锁链伸出回收，双牙交替挥刃并突出第三击。出手残影记录实际出手位置与方向，后续移动和转向不会拖动它；地面边界按掩体裁切，材质效果从实际握持位置抬高绘制。暂停冻结残影，关闭命中闪光保留静态形状。伤害、冷却和成长数值不变。

## 一局流程

- 从船坞选择武器、购买永久升级，再派遣机体。
- 三十个舱室分为接驳防线、冷却花园、记忆档案、地热熔炉和协议中枢五个区域。每区第六舱为区域守卫，第三十舱为深渊主控体。
- 每次清理战斗舱室后，从一至三项有效强化中选择一项，再选择前进路线。
- 普通战斗、精英封锁、补给交换站和维修站提供不同风险与收益。精英更强，舱室奖励翻倍。
- 关卡借鉴手工房型池、分支奖励预告、分批战斗和关间喘息的节奏。五组探索地图与五组守卫地图使用本地插画和对应碰撞，穿插不同隔断、回环与安全舱；敌人会绕过实体掩体。首舱保留教学尺度，后续采用 3200×2100 的大舱室。
- 舱门会提前显示下一间的房型、强化方向和风险。后续战斗分批增援，琥珀标记完整预警后才出现；清完所有波次才可领奖。
- 舱室之间保留本局武器强化、耐久与符文。维修站恢复最大耐久的百分之三十五。
- 击败最终主控体后进入救援结局与本局记录。

## 战斗与武器

**0.15.0：元素联动、守卫机制与简洁战斗界面。** 战斗采用有限增援，近卫、混合与交叉火力交替，每批最多六敌，清完即可领奖。投送有完整预警；每清完一批，为存活队员补修两点耐久。守卫保留更多攻击循环，攻击前摇和伤害保持原值。新增敌人共享原来的整舱废料预算，成长与商店经济保持稳定。速射枪单/双人完整输入机器人实测战斗舱中位数约 111 / 112 秒，近战和精英可能更久；详见[战斗基线](docs/balance.md)。

红色扇区标记近身攻击的完整范围，带箭头的射线预示弹道方向。首领周围的三环预示地面锁定，随后出现的橙色地面圈才是爆炸落点；首领血条旁会显示正在准备的攻击名称。

五名守卫各有专属攻击和图标：封锁卫士用正面横扫，可绕到侧后；冷却看守在每名队员附近铺出依次引爆的三处落点；档案裁决者用交叉光栅封锁直线，四个斜角可避；熔炉监工释放热环，内圈与外圈都安全；主控体依次点亮四片扇区，需要留意倒计时与间隙。图标是准备提示，随后放置的橙色范围至少再预警 0.95 秒；冲刺可躲过，弹反无效，实体掩体仍能保护机体。旧十二舱守卫保留原招式。

共享技能包括等离子弹、冲刺、冰冻新星与弹反。冲刺挡住攻击可触发完美闪避，返还冲刺并短暂增伤。弹反窗口很短；橙色区域爆炸需要移动或冲刺躲避，不能弹反。

十八种基础武器在开局前均可自由选择，战斗中不能换装。主武器攻击不消耗共享的等离子能量。

| 武器 | 攻击特点 |
| --- | --- |
| 刀锋、长枪、重锤 | 均衡扇形斩、远距离窄突刺、重击与强力击退 |
| 双牙 | 快速连击，连续第三击造成双倍伤害 |
| 电弧 | 广角能量扫击，可连锁额外两个目标 |
| 引力锤 | 引力井先吸引敌人，再延迟爆炸 |
| 回旋刃 | 去程与回程各命中一次，飞行中不能再次投掷 |
| 锁链鞭、棱光刃 | 远距离拉回敌人；近战斩击加贯穿能量束 |
| 火焰、冰霜、闪电法杖 | 爆炸火球与燃烧池；贯穿冰弹与叠层冻结；最多四目标连锁闪电 |
| 速射枪、霰弹枪、轨道炮 | 持续射击；七枚短程散弹；蓄力贯穿弹 |
| 速射弓、长弓、风暴弓 | 连续箭；满蓄力贯穿四目标；三箭扇形齐射 |

火焰、冰霜、电击、毒素、汲取和终结六类符文可以叠加在同一把武器上，每类最高三级。火焰能与冰冻产生热冲击，也能点燃毒素。相同的武器自带元素与符文不会重复叠加一次命中。

新战役的元素组合有范围收益：先冻结，再用火焰击碎，热冲击会波及附近敌人；毒素累积至少三层后，火焰消耗全部毒层产生范围爆燃。火毒同武器也能先蓄毒、第三击引爆。可以先用引力井聚怪，或由冰霜/毒素队友铺状态、火焰队友引爆；致命火焰一击仍会触发已有状态。爆发不伤队友，实体掩体会阻挡。祝福卡提示组合，局内构筑列出实际条件、伤害与范围。

战斗 HUD 使用原创技能图标、短名称与实时按键/冷却，保留蓄力、能量不足、瞄准方式和双人修复进度。完整符文放在 Tab 构筑页；重复的进舱/每波大字播报取消，底部遮挡缩小。

## 祝福与成长

**0.12.0：局内构筑与升级对比。** 战斗中按 Tab 查看武器的实际单次伤害、散弹数量或蓄力伤害，以及耐久、机动、能量、当前符文与元素联动。双人模式可分别查看两席。长内容支持滚动与手柄焦点导航。战斗中查看后返回暂停，主动恢复才继续；奖励、路线、商店和维修页查看后回到原来的选项，不刷新奖励或消耗资源。祝福卡与商店显示各自武器和符文的升级前后数值，基础攻击单独标注。

强化卡显示本次提升前后的数值。攻击前期增幅明显，后期采用有上限的增量，避免三十舱的连续乘算失衡；耐久与机动也有明确上限，达到上限的无效强化不再入选。商店调校遵循相同伤害上限。冰霜、电击等符文逐级提高实际效果，同元素武器与符文在一次命中里合并生效。首领有短暂的冻结抗性间隔，汲取有按等级增长的回复预算。数值依据和测试边界见 [平衡说明](docs/balance.md)。

旧版十二舱安全点仍按原地图生成器和原路线继续，直到旧版结局；开始新的救援才进入五区域版本。更新不会重算已经保存的角色属性。

战斗界面会显示当前使用鼠标瞄准、摇杆瞄准还是辅助锁定。鼠标按住攻击、长时间蓄力及松开射击都不会被辅助锁定打断；关闭辅助后，鼠标瞄准始终保持。战斗时显示专用准星，手柄操作隐藏鼠标，进入菜单恢复普通指针。

## 双人手柄 · 同屏共享

标题页选择“双人手柄救援”，两只手柄分别按面板下键加入。先加入为一号席，后加入为二号席；各自用十字键左右选择武器，然后按菜单键出发。双人模式从新救援开始，旧救援存在时仍需确认替换。

两人共享画面和镜头，拉开距离时自动缩放；蓝色一号、金色二号的编号与状态固定对应。每人有独立的移动、瞄准、攻击、技能、武器、耐久和能量，无友军伤害。废料、核心和所选强化共享，维修和调校同时作用于两人。敌人追踪存活目标，双人敌人耐久为单人的 1.6 倍，攻击伤害保持原值。

一人离线后，队友靠近九十单位并停留三秒可修复；移动或受击会中断。清理舱室会自动修复离线队友，恢复最大耐久的百分之三十五。两人都离线才结束救援。共享菜单由一号席控制，一号离线时由二号接管；两人均能暂停。

断开任一已配对手柄会暂停并显示配对页。重新按下键认领空席，再按菜单键返回。双人安全点记录两人的武器、属性和共享进度，续档后重新配对；系统设备编号不会写入存档。单人旧存档继续兼容。

## 2560 × 1440 全屏

使用主菜单/暂停页的“全屏”按钮、F11 或“设置 → 画面与舒适度 → 无边框全屏”进入当前显示器的原生无边框全屏，保持桌面分辨率，不独占切换显示模式。Windows 桌面设为 2560 × 1440 时，游戏使用该分辨率铺满 16:9 画面。界面按显示比例扩展，保持文字比例并增加横向可见区域；其他显示器分辨率按其原生输出适配。macOS 全屏遵循系统报告的刘海安全区域。

## 废料、核心与存档

**废料**用于本局商店，在重新派遣时清零。商店出售应急维修、武器调校和随机元素符文，每项限购一次。

**技术核心**在清理舱室后传回船坞并保存。核心可购买强化机体、武器校准和能量回收三类永久升级，每类最高五级，下一次派遣时生效。武器选择、派遣次数、成功救援次数和最深抵达舱室也会保存。

存档为 Godot 的 `user://profile.cfg`，另保留 `profile.cfg.bak` 备份。可以在 Godot 的“项目 → 打开用户数据文件夹”中找到。永久成长与本局安全点在同一次写入中保存，避免重复领奖。旧版永久成长存档可自动迁移；无法识别的未来版本不会被覆盖。

每次进入舱室、看完剧情、清理战斗、选择强化/路线和购买补给后自动保存。主菜单的“继续救援”恢复上一次安全点；恢复战斗舱时先暂停，按恢复连接再开始。战斗中退出会回到本舱入口，当前战斗中的伤害、击杀和消耗不会保存。死亡或完成救援后，本局存档结束；新救援会先确认替换旧救援。保存失败会在菜单提示。

## 设置与手柄

**0.13.0：终端设置重绘。** 左侧固定导航分为画面、声音、键盘和手柄四类；本地原创显示器、混音台、键盘和手柄图示与实际设置联动。震动与闪光可在独立小画面中预览，战斗保持暂停；声音页可试听提示音，按 M 静音时输出表同步归零。键盘图示高亮当前绑定，修改与取消沿用原有保护。返回恢复进入设置时的焦点，双人断线重新配对后仍回到设置。

主菜单和暂停菜单都可进入设置。支持总音量、战斗音效、环境声、全屏、震动与命中闪光强度，以及辅助瞄准。震动/闪光设为零可关闭；敌人的攻击范围仍会显示。高对比文字选项提高文字亮度并添加描边，可随时切换。首舱提供移动、攻击、冲刺三步短提示，可在设置里关闭。设置单独保存在 `user://settings.cfg`，带有备份恢复与版本保护。

九项主要操作可重绑字母、空格、Shift 或 Ctrl；重复键与菜单保留键会被拒绝，Esc 可取消重绑；使用手柄时可按右键或菜单键取消，录入期间不会误触其他菜单。方向键、鼠标和菜单快捷键始终可用；战斗提示随当前绑定更新。

手柄使用标准 Godot 映射：左摇杆移动、右摇杆瞄准、右肩键攻击、左肩键等离子，右侧四键的下键冲刺、左键冰冻、右键弹反。菜单用十字键导航、下键确认、右键返回、菜单键暂停。手柄断开或应用失去焦点会暂停。键鼠与手柄输入可自动切换；绑定接受系统分配的任意手柄编号。已验证编号 0、1、3 的模拟事件与非零编号菜单流程；实体手柄专项验收按用户要求在本次交付中跳过。

“操作指南”介绍危险前摇、资源用途与完整按键；长内容可滚动，手柄焦点移动会让对应内容进入视野。

## 验证

```sh
python3 verify.py
```

该命令依次完成 Godot 资源导入与二十五套真实场景检查：

- `tests/smoke.gd`：移动、碰撞、技能、三十舱室流程、胜负与重开。
- `tests/weapons.gd`：十八种武器的伤害、穿透、回程、蓄力、元素与掩体。
- `tests/campaign.gd`：房间可达性、实际绕障、路线、商店、永久成长和隔离存档。
- `tests/story_locale.gd`：完整剧情顺序、暂停与继续、中文界面、字体覆盖和菜单尺寸。
- `tests/production.gd`：设置读写/恢复、物理按键事件、菜单与手柄映射、防误触、失焦与声音池，以及完全由十字键/确认键驱动的武器库、设置、升级、商店、剧情与结算流程；用原生渲染执行时还会将截图写入忽略的 `builds/qa/`。
- `tests/checkpoints.gd`：两条路线在每个安全点自动写盘、销毁游戏并重新读取，直到结局；检查商店/核心/修复不重复、旧存档迁移、非法数据拒绝与备份恢复。
- `tests/animation.gd`：正常游戏里的实际移动、撞墙停步、冲刺、八方向步态和双手武器握持；原生执行输出姿态检查图。
- `tests/presentation.gd`：八方向武器发射点与地面碰撞坐标、掩体遮挡、边缘和首领镜头、首领血条与实际阶段、八方向近战预警与真实命中边界、首领预告弹道与实际发射方向。

## 项目结构

`scenes/` 保存主场景、玩家、敌人和弹体；`scripts/` 将战斗、武器、房间、成长、存档、剧情和界面分开；`assets/` 包含运行所需的贴图、图标和开源中文字体。项目不依赖原 HTML 或 `output/` 目录。

本版提供单人键鼠/手柄，以及双手柄本地同屏合作。触屏、武器异相和专属强化尚未移植。角色使用八方向分部位关节动画，按碰撞后的真实移动推进步态；枪械和弓使用绘制贴图，并让双手跟随握把、护木和弓弦。已具备 Mac 本地发行候选包，尚未制作网页发行包，也没有接入 GitHub Pages；原浏览器版本保留在 `../abyss-protocol/index.html`。

正式交付的验收清单与当前证据见 [production-readiness.md](docs/production-readiness.md)。本地 Mac 候选包已经建立；当前文档不构成公开发布、Apple 公证或所有硬件均已实测的声明。

## Mac 本地导出

从 Godot 官方对应版本的 `export_templates.tpz` 中，把 `templates/macos.zip` 和 `templates/version.txt` 解压到本项目的 `builds/templates/`，然后执行：

```sh
python3 export_macos.py --rendered
```

脚本检查引擎与模板版本、运行全部验证、导出通用 Mac 应用、验证压缩包与本地签名，再从独立目录运行发行包里的完整战役自检。`--rendered` 使用静音的原生窗口验证战役、首次存档与冷启动续档；省略时使用无界面检查。输出 `.zip`、SHA-256 校验与构建记录到 `builds/`。`--skip-checks` 只用于刚通过源码验证的工作树；不会跳过独立发行包自检。

当前源码 `0.17.0` 是五区域候选版本，Mac 包使用 ad-hoc 签名，未经过 Apple 公证、未上传。包含 Apple Silicon 与 Intel 二进制；实际验证平台为 Apple M4 Pro，Intel Mac 尚未实测。

导出后的运行资源全部打包，测试源码和构建目录排除。发行模板不支持编辑器的 `--script` 入口，因此使用显式 `-- --verify-release` 自检参数：默认禁用玩家存档读写，在真实发行程序内检查武器、剧情、三十舱室和胜负后退出。导出脚本还创建独立且带标记的临时存档目录，分别启动两个发行进程：首次游玩并购买强化，关闭后重新加载设置、按键和商店记录，再完成结局。这些文件与正式玩家数据隔离。普通启动不运行这些检查。

它核对本版程序、资源包和验证脚本，再在 Windows 本地临时目录运行窗口自检，

```powershell
$env:GODOT_BIN = 'C:\Tools\Godot\Godot_v4.7.2-stable_win64_console.exe'
python prepare_windows_templates.py
python export_windows.py --rendered
```

模板准备脚本从 Godot 官方发布下载，并校验固定 SHA-256 后提取 x86_64 模板；约 1.28 GB 的原始模板包缓存在忽略的 `builds/templates/`。

输出 `builds/深渊协议-0.17.0-Windows-x64.zip`、SHA-256、逐文件校验清单与构建/运行报告。Windows 包当前未进行发行者证书签名，只交付到授权共享盘，未上传公共发行渠道。

Mac 上也可交叉导出：`python3 export_windows.py --wine '/absolute/path/to/wine' --rendered`，需要 PowerShell 7。Wine 仅用于开发验证，不随玩家包分发，记录明确标为兼容层证据。复用前次初始化的独立测试 prefix 需传 `--wine-prefix`，且目录必须带 `.abyss-wine-fixture` 标记；不会使用默认 `~/.wine`。
没有 Windows/Wine 时，只有显式 `--structural-only` 才会跳过运行验证，报告保留“未运行”。交叉导出成功或 Wine 通过均不代表已完成 Windows 实机、显卡和实体手柄验收。

## 本轮视听升级

采用工业空间站方向：原创轨道栖居站插画、暖白正文、救援橙操作重点；普通舱室减少装饰圆环和高频地板噪声，增加检修道、舱壁、舱室编号与有实体碰撞的设备。设备挡住七号时会半透明，首领战镜头同时照顾玩家与首领。界面与标题分别使用本地 Noto Sans / Noto Serif CJK 字体。

枪械、弓、近战器械与法杖各有握持和材质细节；弹体从绘制枪口/箭头位置出现，碰撞仍在统一地面坐标计算。枪械、刀刃、弓弦、重击、电弧、冲刺、命中与界面使用独立合成声，十二路固定声音池避免密集战斗中无限增加音频节点。
