深渊协议 __ABYSS_VERSION__ · Windows 实机验收

一、自动验收
在 Windows 电脑上双击同目录的“一键Windows验收.cmd”。不需要安装 Godot 或 Python，不需要管理员权限。
程序会先校验游戏与验证脚本，然后依次打开测试窗口，验证单人、双人、剧情及存档续玩。
测试资料写入 Windows 本地临时目录，不读取或覆盖正式玩家存档。
修订 4 会显示工具修订号，并预先检查本地目录的创建、写入和重命名权限。
TEMP 不可写时，会尝试当前用户的 LocalAppData\AbyssProtocol-QA；不修改系统或共享盘权限。
通过后，先在本地生成只含报告、日志、截图和校验凭据的 diagnostics 目录及 ZIP，再复制到当前目录的“验收记录”下。
若共享盘拒绝写入，会明确显示“游戏自动测试通过，但报告回传失败”，并显示本地报告目录和失败目标。
此时不需要管理员权限，也不需要因为回传失败而再次测试；资源管理器会选中可直接转交的本地 ZIP。
双击“仅回传验收报告.cmd”可以整理并补传本版最近一次通过的报告，不会启动游戏。
它只查找当前用户 TEMP 或 LocalAppData\AbyssProtocol-QA 中本工具标记的测试目录，核对本版程序和资源哈希及全部阶段结果。
窗口会显示所选报告的路径、时间和测试摘要。找不到匹配报告时会停止，不会代为重跑；请保留旧窗口的测试日志路径。
已有完整或半截回传目录会保留，补传写入带 retry 后缀的新目录。
共享盘仍拒绝写入时，请转交资源管理器选中的 ZIP，或将 ZIP 复制到你有写权限的位置；不必复制整个游戏。
如原测试使用了另一个 TEMP 位置，也可在 PowerShell 中明确指定原测试日志目录和可写的回传目标：
powershell.exe -NoLogo -NoProfile -ExecutionPolicy Bypass -File ".\Run-Windows-Acceptance.ps1" -ReportOnly -RunDirectory "C:\原测试目录\abyss-windows-运行编号" -DestinationRoot "D:\可写报告目录"
请将示例路径换成实际目录；-RunDirectory 指向包含 report.json 的 abyss-windows-… 目录。
不要复制整个测试目录；只复制显示的 diagnostics 目录，其中不含 profile/settings 文件。
脚本仅为本次 PowerShell 进程使用执行策略参数，不修改系统的执行策略。
若失败，请保留终端显示的具体阶段、完整路径和错误信息。原始日志会留在本地。
退出码 0 表示测试及回传均成功；2 表示测试通过但回传失败；1 表示测试或本地报告准备未完成。
共享盘上完整复制结束后才生成 handoff.json；本地诊断目录也保留与报告哈希绑定的凭据。

二、实体双手柄试玩
自动检查通过后，正常打开“深渊协议 __ABYSS_VERSION__”文件夹中的 AbyssProtocol.exe。
正常游戏会使用自己的正式存档；需要保留当前救援时不要确认替换它。
将 Windows 桌面设为 2560×1440，用 F11 切换全屏，确认画面铺满、文字清楚、两人的状态不裁切。
主菜单选择“双人手柄救援”，两只手柄分别按面板下键加入；十字键左右选不同武器，菜单键出发。
分别移动、瞄准、攻击和使用技能，确认没有串键；两人走到场景两端，确认共享镜头能容纳两人。
断开一只手柄，确认游戏暂停；重新接入、认领空席，再继续。
确认倒地修复、双方补给、选强化、跨舱室、继续救援以及结算重开都符合预期。
留意有无黑屏、声音异常、明显掉帧、误操作或看不懂的提示。

三、反馈
可在“验收记录”中新建“试玩反馈.txt”，写下：
Windows 版本、两只手柄型号、显卡及桌面分辨率；上述操作是否正常；遇到问题时的舱室、武器和复现步骤。
这些真人反馈与自动运行报告分开记录，自动检查通过不等于实体手柄或游戏体验已经验收。
