# 深渊协议：穹灯站救援

## 核心冲突

深渊协议是一套保护空间站的应急程序。损坏的温控传感器发出持续过热读数，它因此封锁通道并调动防御设备。供给防御的电力来自散热泵，错误的判断开始造成真正的危机。

七号不能直接关掉主控，因为休眠舱的维生系统也依赖它。救援需要三件事：恢复实际供电、获得人工接管密钥、提交独立仪表的校准数据。最终战的目标是压制主控的防御模块，让维修握手完成，而非炸毁承载乘客的空间站。

## 人物与因果

- **七号**：船坞的维修机器人，也是玩家操作的角色。每次机体失效前，维修记录会传回船坞；重新派遣的机体继承已保存的技术方案。局外成长由此有了世界观依据。
- **林澈**：首席工程师。她未能完成抢修，但留下了应急留言、维修总线和授权记录。故事没有断言她已经死亡；她的最终去向不影响本次救援的因果闭环。
- **深渊主控**：相信错误数据的应急系统，并非无缘无故出现的恶意反派。结局中，它收到正确数据后撤销封锁，将防御资源转为救援资源。
- **三百一十二名乘客**：始终被困在休眠舱，生命维持尚未失效。人数在开场、调查和结局中一致。

五区依次为接驳防线、冷却花园、记忆档案、地热熔炉、协议中枢；每区六舱，每区最后一舱由守卫封锁。旧十二舱存档保留第三、六、九、十二舱的原触发位置。

## 六个剧情节点

| 节点 | 玩家此时知道什么 | 推进的实际目标 |
| --- | --- | --- |
| 派遣进入第一舱 | 空间站失联，仍有乘客存活 | 接通维修总线，恢复沿途供电 |
| 第三舱事故记录 | 原始警报不可信，封锁正在制造新危机 | 找到人工授权，避免直接断电 |
| 击败第六舱卫士 | 林澈留下有效的接管命令 | 取得接管密钥，打开冷却与档案总线 |
| 第二十一舱独立读数 | 温控传感器确实失效，泵组仍可恢复 | 保存校准数据，恢复散热 |
| 第三十舱核心 | 数据与授权齐备，防御模块仍阻止维修 | 压制防御，完成维修握手 |
| 最终战胜利 | 主控修正风险评估 | 撤销封锁，护送乘客归航 |

路线影响战斗风险、补给与强化，不改变这些必经线索。剧情阅读时世界暂停；重复点击不会跳过下一节点。失败进入机体离线界面，只有最终核心战胜利才会播放救援结局。

## 语气与呈现

使用简洁的维修记录与应急录音，让玩家逐步理解事故原因。避免把主控简单写成“突然叛变”，也避免在开场一次解释完所有真相。最终回应开场的应急留言：从无人回应的失联空间站，走到主动发出归航广播。

实际游戏文本集中在 `scripts/story.gd`，本文件描述设定与约束，不是第二份独立剧情文本。
